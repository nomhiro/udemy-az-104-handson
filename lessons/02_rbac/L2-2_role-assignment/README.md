# L2-2 スコープを変えてロールを割り当て、アクセスを確かめる

Azure RBAC で、リソース グループごとに違うロールを割り当てます。割り当てた結果は「アクセスの確認」で確かめ、上のスコープから届く（継承される）割り当ても見ます。最後に割り当てを外し、作ったものを削除します。

- 所要時間: 約20分
- 費用: 作るのは、リソース グループ、セキュリティ グループ、ネットワーク セキュリティ グループだけです。仮想マシンのような、動かしている間に料金のかかるリソースは作りません。最後にすべて削除します
- 割り当て先は、ユーザーではなくセキュリティ グループにします。新しいユーザーを作らずに試せます

## 前提

- サブスクリプションの **所有者** のロール（ロールを割り当てるため）
- Microsoft Entra ID で、グループを作れること（既定では、メンバーのユーザーはセキュリティ グループを作れます。組織の設定で止められているときは、管理者に頼んでください）
- Azure portal の言語は日本語（右上の歯車 >「言語と地域」）

## このレッスンで作るもの

| 種類 | 名前 | 場所 |
|---|---|---|
| リソース グループ | `rg-az104-l22-web`・`rg-az104-l22-db` | 東日本（Japan East） |
| セキュリティ グループ | `Web運用チーム`（メンバーは入れません） | Microsoft Entra ID |
| ネットワーク セキュリティ グループ | `nsg-az104-l22` | `rg-az104-l22-web` の中 |
| ロールの割り当て | `Web運用チーム` に、`rg-az104-l22-web` で閲覧者、`rg-az104-l22-db` で共同作成者 | |

## 手順

### 1. リソース グループを2つ作る

1. portal の上の検索欄に「リソース グループ」と入れ、候補の「リソース グループ」を選びます
2. ［＋ 作成］を選び、［基本情報］タブに次のとおりに入れて、［レビューと作成］>［作成］を選びます
   - サブスクリプション: お使いのサブスクリプション
   - リソース グループ名: `rg-az104-l22-web`
   - リージョン: (Asia Pacific) Japan East
3. 同じように、`rg-az104-l22-db` も作ります
4. リソース グループの一覧の絞り込み欄に `rg-az104-l22` と入れ、2つあることを確かめます

### 2. セキュリティ グループを作る

1. 上の検索欄に「Microsoft Entra ID」と入れ、候補を選びます
2. 左のメニューの［管理］>［グループ］を選びます。「グループ | 概要」が開くので、上の［新しいグループ］を選びます
3. 次のとおりに入れて［作成］を選びます
   - グループの種類: セキュリティ
   - グループ名: `Web運用チーム`
   - メンバーシップの種類: 割り当て済み
   - 所有者・メンバー: 選ばない
4. 左のメニューの［すべてのグループ］を選び、`Web運用チーム`（グループの種類: セキュリティ）があることを確かめます（表示まで少しかかることがあります。［最新の情報に更新］を選びます）

### 3. rg-az104-l22-web で、閲覧者を割り当てる

1. リソース グループの一覧から `rg-az104-l22-web` を開き、左のメニューの［アクセス制御 (IAM)］を選びます
2. ［＋ 追加］>［ロールの割り当ての追加］を選びます
3. ［ロール］タブの［職務ロール］で `閲覧者` を選び、［次へ］を選びます
4. ［メンバー］タブで、アクセスの割り当て先を「ユーザー、グループ、またはサービス プリンシパル」にし、［＋ メンバーを選択する］を選びます
5. 検索欄に `Web運用チーム` と入れて選び、［選択］を選びます
6. ［レビューと割り当て］タブで、ロール・スコープ・メンバーを確かめ、［レビューと割り当て］を選びます

### 4. rg-az104-l22-db で、共同作成者を割り当てる

1. `rg-az104-l22-db` を開き、［アクセス制御 (IAM)］>［＋ 追加］>［ロールの割り当ての追加］を選びます
2. ［ロール］タブの［特権管理者ロール］で `共同作成者` を選び、［次へ］を選びます。「アクセス権がより少ない職務ロールを代わりに使用できますか?」と出ます。共同作成者は、すべてのリソースを管理できる特権管理者ロールなので、職務ロールで足りるなら、そちらを選ぶように、という注意です
3. 手順3の 4〜6 と同じように、`Web運用チーム` を選んで割り当てます

### 5. アクセスの確認で、スコープごとのロールを見る

1. `rg-az104-l22-web` の［アクセス制御 (IAM)］>［アクセスの確認］タブで、［アクセスの確認］を選びます
2. 右に開く「アクセスの確認」の検索欄に `Web運用チーム` と入れ、出てきたグループを選びます
3. 「Web運用チーム 割り当て - rg-az104-l22-web」の「現在のロール割り当て」に、閲覧者が「このリソース」のスコープで出ることを確かめます
4. `rg-az104-l22-db` でも同じように確かめます。こちらは共同作成者です

同じグループでも、リソース グループごとに違うロールになっています。ロールは、割り当てたスコープの中にだけ届きます。

### 6. 中のリソースで、継承された割り当てを見る

1. 上の検索欄に「ネットワーク セキュリティ グループ」と入れ、候補を選びます
2. ［＋ 作成］を選び、次のとおりに入れて［確認および作成］>［作成］を選びます
   - リソース グループ: `rg-az104-l22-web`
   - 名前: `nsg-az104-l22`
   - リージョン: Japan East
3. できたら［リソースに移動］を選び、左のメニューの［アクセス制御 (IAM)］>［ロールの割り当て］タブを開きます
4. 検索欄に `Web運用チーム` と入れ、閲覧者の行のスコープが「リソース グループ (継承済み)」になっていることを確かめます

リソースでは割り当てていないのに、リソース グループで割り当てた閲覧者が届いています。これが継承です。

### 7. ロールの定義を読む

1. ［アクセス制御 (IAM)］の［役割］タブで、`閲覧者` の行の［ビュー］を選びます（手順6の `nsg-az104-l22` の画面から続けてかまいません。ロールの定義は、どのスコープで開いても同じです）
2. ［JSON］タブで、`actions` が `*/read`（すべてのリソースの読み取り。データの読み取りは含まない）だけであることを確かめます
3. 同じように `共同作成者` を開き、`actions` が `*`（すべての操作）で、`notActions` に `Microsoft.Authorization/*/Write`（ロールの割り当ての作成などを含む）が入っていることを確かめます

### 8. 割り当てを外す

1. `rg-az104-l22-web` の［アクセス制御 (IAM)］>［ロールの割り当て］タブで、検索欄に `Web運用チーム` と入れます
2. 閲覧者の行のチェック ボックスを選び、［削除］>［はい］を選びます
3. 一覧から消えたことを確かめます

### 9. 後片付け

1. `rg-az104-l22-web` の［概要］で［リソース グループの削除］を選びます。一緒に消えるリソース（`nsg-az104-l22`）が表示されます。確認の欄にリソース グループの名前を入れて［削除］を選び、「削除の確認」でもう一度［削除］を選びます。中のリソースも一緒に消えます
2. `rg-az104-l22-db` も同じように削除します
3. Microsoft Entra ID の［グループ］>［すべてのグループ］で `Web運用チーム` のチェック ボックスを選び、［削除］>［OK］を選びます
4. リソース グループの一覧の絞り込み欄に `rg-az104-l22` と入れ、何も出ないことを確かめます（削除には数分かかることがあります）

Cloud Shell でも確かめられます。

```bash
az group list --query "[?starts_with(name, 'rg-az104-l22')].name" -o tsv
az ad group list --display-name "Web運用チーム" --query "length(@)"
```

1つ目は何も出ず、2つ目は `0` なら、片付けは終わりです。

## うまくいかないとき

- **［ロールの割り当ての追加］が選べない**: サブスクリプションかリソース グループで、所有者（またはユーザー アクセス管理者、Role Based Access Control Administrator）のロールが要ります
- **メンバーの検索にグループが出ない**: グループを作った直後は出ないことがあります。少し待ってから、もう一度検索します
- **アクセスの確認に割り当てが出ない**: ロールの割り当てが反映されるまで、最大で10分ほどかかることがあります。［最新の情報に更新］を選びます
